# 蟑螂封鎖器（IG / Threads Cockroach Blocker）

> **v0.12** · 支援 繁體中文 / 簡體中文 / 日本語 / English
> · Instagram 與 Threads 同時並行執行 · 不需程式能力

定期在 **Instagram 網頁版** 與 **Threads 網頁版**，自動批次封鎖帳號名稱含指定關鍵字的帳號，並連帶封鎖該使用者未來新建的帳號。給完全不懂程式的人用：開視窗、輸入關鍵字、按幾個按鈕就好。

---

## 這個工具解決什麼問題

你被某個或某一群人在 IG / Threads 上洗版、跟追、留言騷擾。對方會不斷開新小帳（「蟑螂」），你手動封一個他開一個，永遠封不完。本工具做兩件事：

1. **定時掃**：每天在你設定的時間（例如中午 12:00、晚上 22:00）自動開瀏覽器，搜尋你給的關鍵字（例如 `foodie`、`bot`、對方固定用的前綴），把符合條件的新帳號全部封掉。
2. **連帶封未來帳號**：封鎖時一併使用 IG 內建的「封鎖此帳號及其建立的其他帳號」機制。這是 Meta 自己的反跟騷機制，比你手動追殺小帳有效。

### 功能清單

| | 說明 |
|---|---|
| **多語系** | 右上角下拉選單：繁體中文 / 簡體中文 / 日本語 / English。第一次啟動跟著作業系統語言，之後記住你的選擇 |
| **並行執行** | 同時啟動 **Instagram 與 Threads** 兩個獨立瀏覽器，不再一個跑完才跑下一個 |
| **嘗試上限** | 每輪最多實際觸發幾個候選。避免封鎖失敗時（例如網站改版），「最多封鎖幾個」永遠不會滿，程式把全部候選跑完 |
| **可中斷** | 按「停止」約 1 秒內中斷，不用等目前那個帳號跑完 |
| **中文字型** | 自動安裝 Chiron GoRound TC 字型（含中半粗），無法安裝時自動退回系統字型 |
| **預設演練** | 第一次開啟一定是演練模式，只列出「會封誰」而不會真的封任何人 |

## 給一般使用者：上手步驟

### 第一步：下載

下載並解壓縮整個 `dist\CockroachBlocker\` 資料夾（**整個資料夾都要拿，不只是 .exe**）。
若要自行執行原始碼，才需要另外裝 Python 3.10 以上版本：

```bat
build.bat
```

### 第二步：啟動

```bat
dist\CockroachBlocker\CockroachBlocker.exe
```

想用原始碼跑就 `python main.py`。會出現一個視窗，三個分頁。

### 第三步（中文字型，選裝）

```bat
install_fonts.bat
```

裝 Chiron GoRound TC 字型（含中半粗），介面會好看很多。**這是選用的**——沒裝也能正常運作，只是會用系統字型。
字型是安裝給「目前這個 Windows 使用者」，不需要管理員權限。已經開著的程式在安裝完成後會立刻套用，不必重開。

### 第四步：設定 + 登入

1. 在「設定」分頁輸入關鍵字（例如 `foodie`），設定每天執行時間（每行一個 `HH:MM`）。
2. **保持勾選「⚠ 演練模式」**，按 **「立即跑一輪」**。程式只會搜尋、判斷，然後在「執行紀錄」列出「它打算封哪些帳號」，**不會真的封任何人**。先確認名單合理。
3. 名單沒問題後，**取消勾選演練模式**。
4. 按 **「① 登入 Instagram」**，會跳出瀏覽器視窗，在那裡平常一樣登入你的 IG。登入完成後回到主視窗按「完成登入」。**瀏覽器視窗不要關**。
5. 同樣方式登入 Threads（**非必要**，見下方「Threads 的現況」）。
6. 按 **「開始排程」**。

就這樣。之後它每天自己跑，你可以在「執行紀錄」分頁看它封了哪些。

> 如果沒登入就按「立即跑一輪」，會看到「！登入狀態失效」，請先完成第 4 步。

## ⚠ Threads 的現況（請先看這段）

**Instagram 的搜尋、判斷、封鎖按鈕都經過實測；Threads 的搜尋與判斷也已實測，但封鎖按鈕還沒。**

| | Instagram | Threads |
|---|---|---|
| 搜尋 | ✅ 已實測 | ✅ 已實測（必須切到「個人檔案」分頁才有帳號） |
| 判斷（粉絲數／已追蹤／藍勾勾） | ✅ 已實測 | ✅ 已實測 |
| **封鎖按鈕** | ✅ 已實測到確認彈窗 | ❌ **未驗證** |

Threads 2026/09 實測發現並已修正的問題：

- Threads 搜尋預設停在「最相關」分頁，那裡**全是貼文**（作者跟關鍵字無關）。
- 必須自動切到 **「個人檔案」分頁** 才是真正的帳號搜尋結果。
- 修正後同一個關鍵字 `foodie`：候選數從 **0 → 22**。

如果 Threads 封鎖真的失敗，程式會把截圖存在 `debug\` 資料夾，把那些截圖傳過來就可以定位。

### IG 搜尋只有 5 筆？—— 已修正

2026/09 實測發現 **IG 的搜尋 API 對同一個字串永遠只回 5 筆**，回應裡雖然帶了 `has_more: true`，但那個端點不接受任何分頁參數（各種頁面狀態、各種 App-ID 都一樣）。

症狀是：關鍵字 `foodie` 一輪只有 2 個候選，扣掉藍勾勾與大粉絲後常常剩 0 個，看起來像「不到 10 個就結束」。

修正方式：**不同字串會回完全不同的 5 筆**。所以現在對同一個關鍵字會用多種寫法各查一次再累積（原文、`關鍵字_`、`_關鍵字`、`關鍵字1`、`a關鍵字`，以及逐字縮短的前綴 `f` / `fo` / `foo` / …），八種寫法在瀏覽器裡並行發出。實測同一個關鍵字 `foodie`：

| | 修正前 | 修正後 |
|---|---|---|
| 原始結果 | 5 筆 | **26 筆** |
| 過濾後候選 | 2 個 | **11 個** |
| 搜尋耗時 | — | 約 3 秒（8 個查詢並行送出） |

不相關的結果會被「只處理含關鍵字的帳號」擋掉，所以多查不會增加誤封。

## 篩選規則

| 設定 | 預設值 | 說明 |
|---|---|---|
| **關鍵字** | `foodie` | 逗號分隔。填對方不斷開小帳時用的詞，不暴露對方使用的詞，例如 `spam`、`bot`、名稱前綴 |
| **演練模式** | 開 | 只搜尋與判斷、列出會封誰，完全不點封鎖。**要真的封鎖請取消勾選** |
| **只處理含關鍵字的帳號** | 開 | IG 搜尋是模糊的，關掉會讓很多不相關的帳號一起進來 |
| **跳過藍勾勾** | 開 | 正經 KOL 會被跳過 |
| **跳過已追蹤** | 開 | 不要封自己跟的人 |
| **粉絲數門檻** | 5000 | 粉絲數高於設定數量視為正常帳號，不封鎖 |
| 每個帳號封鎖前等待 | 固定 | 在設定頁可直接改秒數 |

## 執行上限

| 設定 | 預設值 | 說明 |
|---|---|---|
| 每輪最多封鎖幾個 | 10 | 保守值。建議先用 5 試 |
| 每輪最多實際觸發幾個 | 60 | 嘗試上限。封鎖失敗時會用到，0 = 自動（不少於 30） |
| 每日執行時間 | 12:00 / 22:00 | 每行一個，格式 `HH:MM` |

## 封鎖了就沒了？

| 情況 | 建議做法 |
|---|---|
| 對方已把你封了但帳號還在 | 對方看不到你的帳號。可用「引述」看對方在什麼時候引用你，把那些詞加進關鍵字 |
| 對方持續開新帳號 | 每天多設兩個時間點跑，關鍵字多填幾個相似的 |
| 對方改名重開 | 不要只放「全名」。放上對方暱稱、頭像特徵、常見詞彙 |
| 對方不用本名 | 若無法從追蹤判斷，就看對方是否在內容裡 tag 你，把那些 tag 當關鍵字更有效 |
| 對方常常主動來找你 | 這就不是關鍵字能解決的問題，需要在 Meta 檢舉工具裡處理 |

## 常見問題

**Q: 出現「登入狀態失效」**

A: 登入狀態消失了。重新按「① 登入 Instagram」。**瀏覽器視窗不要關**，等登入完成後按主程式的「完成登入」。

**Q: 出現「登入未完成」**

A: 這是保護機制。IG 可能因為操作太快把你導去登入頁或 reels 頁。照著網址看一下實際跳去哪，若反覆出現就把「每輪最多封鎖幾個」降到 3、「每輪最多實際觸發幾個」降到 10。

**Q: 一輪下來不到 10 個就結束了？**

A: 多半是搜尋撈到的候選本來就少，或被門檻篩掉了。2026/09 之前 IG 搜尋 API 每個字串只回 5 筆，是已知並已修正的問題（見上方「IG 搜尋只有 5 筆」）。現在若仍偏少，代表粉絲數門檻太高——把門檻調高或調到 0 看看會多出多少。

**Q: 對方粉絲數讀不到／抓不到正確數字**

A: 先開「演練模式」按「立即跑一輪」，看「執行紀錄」分頁。如果連「會封」都沒列出，代表是搜尋或門檻把它篩掉了（最常見是粉絲數門檻太高）。

**Q: 對方粉絲數門檻設為 0 還是可以封？**

A: 正常。每個帳號的判斷順序是：藍勾勾 → 已追蹤 → 粉絲數。請一個一個排出你真正想封的那幾個。

**Q: 程式結果是錯的帳號**

A: 看「執行紀錄」分頁的說明。粉絲數讀不到會寫「讀不到粉絲數」，程式會略過門檻直接判斷。正常資料結構是「X 位粉絲」後面的數字對到了才算得到（只有「萬」或「億」時才需要換算）。

**Q: 視窗可以關掉嗎？**

A: 不可以。程式需要保持瀏覽器在目標帳號頁面才能判斷。若中途關掉，下一輪重新啟動就可以。

**Q: 這樣會不會被 IG 封鎖？**

A: 有可能。自動化操作本來就有風險，程式內建了嘗試上限、隨機等待與截圖除錯來降低機率，但不保證。

**Q: 程式會不會自己封我？**

A: 不會。程式會跳過：自己的主頁、已追蹤的帳號、藍勾勾帳號、粉絲數超過門檻的帳號、已經封過的帳號。

## 開發者注意：字元碼點對照

這個程式要在網頁上找「封鎖」按鈕，字元必須精確。已用系統字型放大比對確認下列對照：

**請勿把字形相近的字當成相同的字**：

| 碼點 | 字 | 說明 |
|---|---|---|
| `U+9396` | 鎖 | ✅ 正體。繁中 IG / Threads 實際用這個 |
| `U+9501` | 锁 | 簡體。中國版介面用這個 |
| `U+9392` | 鎒 | ❌ 形近但不是「鎖」，對不上 |
| `U+93B6` | 鎶 | ❌ 形近但不是「鎖」，對不上 |
| `U+6EFF` | 滿 | 形近字，參考用 |

`blocker/instagram.py` 的正則用 Unicode 跳脫序列寫死，避免日後編輯時被形近字取代：

```python
BLOCK_ITEM_RE = re.compile("^\\s*(\u5c01\u9396|\u5c01\u9501|Block)\\s*$")
#                  封鎖     封锁
```

若要新增中文字串，請先確認碼點：

```bat
python -c "print([hex(ord(c)) for c in 'YOUR_TEXT'])"
```

## 建置注意事項

- `build.bat` 必須維持**純 ASCII**。cmd.exe 會用系統 ANSI 碼頁讀 `.bat`，中文會讓指令亂掉。
- `install_fonts.ps1` 必須存成 **UTF-8 with BOM**，否則 PowerShell 解析會失敗。
- PyInstaller 用 `--collect-all playwright`，且選 onedir 模式（onefile 與 Playwright 相衝）。
